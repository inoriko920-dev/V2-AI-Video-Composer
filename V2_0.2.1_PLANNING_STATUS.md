## STEP 02 locked decisions
- FFmpeg CLI remains the reference/final renderer; no renderer rewrite or new imaging dependency.
- Preview uses two tiers: lightweight live Qt for cheap properties and responsive Qt approximation + exact asynchronous FFmpeg truth-preview for blur/shadow/glow.
- Final stage order is fixed: RGBA/decode → crop clip → blur → scale → rotation → mask → shadow/glow → opacity → position/overlay.
- Four-side crop is implemented as stable-canvas dynamic alpha clipping, not dynamic FFmpeg geometry crop.
- Blur uses a named gblur + sendcmd candidate path and is blocked behind a frame-accurate Windows prototype gate.
- Shadow/glow use alpha-derived branches and share the heavy command scheduler; transparent-alpha artifacts are a promotion gate.
- Advanced capability detection is feature/micro-render based and project-aware, not version-string based.
- Heavy preview is cancellable, revision-safe and cache-bounded.
- Performance budgets and real-render proof matrix are frozen.
- Bezier/velocity/overshoot remain compatible with the shared scalar architecture.
- Missing required advanced-v1 backend capability fails preflight; no silent quality fallback.
