## STEP 03 locked decisions
- Schema v3 remains legacy-compatible; schema v4 represents an explicitly activated advanced-v1 project.
- `metadata["animation_keyframe_contract"]="advanced-v1"` is mandatory for schema v4 and forbidden on schema v3.
- Automatic migrations remain v1→v2→v3 only; there is NO automatic v3→v4 migration.
- New/opened projects remain v3 until the first successful advanced edit.
- First advanced edit promotes schema + marker + track atomically as one history entry.
- Dormant advanced tracks in v3 are preserved but inactive; unrelated dormant tracks require one-time activation acknowledgement before project-wide activation.
- Normal Save cannot downgrade an existing v4 file to v3.
- First v3→v4 overwrite creates a non-clobbering `.pre-schema-v4.bak`.
- Recovery may explicitly cross v3/v4 boundaries only after validation and pre-recovery backup.
- Copy Scene Animations preserves complete assignment data and lock state but never promotes v3.
- Removing the last advanced track does not auto-demote a v4 project.
- Validation warning/error codes and backward-compatibility guarantees are frozen.
