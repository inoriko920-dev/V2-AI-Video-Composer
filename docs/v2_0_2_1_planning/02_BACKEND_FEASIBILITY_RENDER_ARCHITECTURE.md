Status: **PASS**

## Frozen architecture decisions

### Renderer strategy
- Keep FFmpeg CLI as the reference/final renderer.
- No renderer replacement and no new runtime imaging dependency is authorized by STEP 02.
- Existing v0.2.0 transform/preset paths remain the regression baseline.

### Preview strategy
Two preview tiers are required:
1. **Lightweight live Qt preview** for position, scale, rotation, opacity, crop visibility and mask progress.
2. **Heavy interaction approximation + exact FFmpeg truth-preview** for blur, shadow and glow.

Qt heavy effects are responsive editing aids only and must not be described as pixel-identical to FFmpeg.
Exact heavy parity is established by an asynchronous FFmpeg truth-preview generated with the same compiler path used for final render.

Truth-preview requirements:
- debounce/scrub settle: approximately 200–300 ms;
- use JobManager cancellation;
- use generation/revision IDs so stale frames cannot replace newer preview;
- cache key includes source fingerprint, Scene/animation revision, resolution and FFmpeg capability fingerprint;
- bounded cache only; no heavy work on the GUI thread.

### Final per-asset filter order
1. decode / format=rgba / setpts;
2. crop visibility clip;
3. blur;
4. scale;
5. rotation;
6. mask progress;
7. shadow + glow branch/composite;
8. final group opacity;
9. position / overlay.

Legacy preset transforms remain additive within their matching stage.

### Opacity
- GO.
- Preview uses scalar evaluator + QPainter opacity.
- Final render applies dynamic alpha to the completed per-asset visual group.
- Do not place opacity before shadow/glow because the locked composition contract applies it after the group is assembled.

### Crop
- GO using a **stable-canvas alpha visibility clip**, not FFmpeg geometry crop.
- Direct FFmpeg `crop` is rejected for four-side keyframe geometry because output width/height are not ordinary per-frame expressions while x/y can vary per frame.
- Preview clips the asset visibility while preserving stable coordinates.
- Final render expresses the crop visibility window in alpha using spatial/time expressions on a fixed-size RGBA canvas.
- Reapply the crop alpha boundary after blur when required so hard crop semantics are preserved.

### Mask progress
- GO.
- v0.2.1 semantics remain hard-edge left-to-right reveal.
- Preview uses clipping.
- Final render uses dynamic spatial alpha gating on a stable canvas.
- Crop and mask are separate semantic stages and are only merged when ordering can be proven equivalent.

### Dynamic alpha compiler
- FFmpeg spatial alpha expressions are built using an RGBA-capable path with X/Y/time-aware evaluation.
- Expressions are generated by a central escaping/compiler helper.
- Generic arbitrary opacity is not delegated to a scalar-only alpha option that cannot express the locked time curve.
- Crop/mask/opacity must preserve premultiplied-alpha correctness through heavy effects.

### Blur
- **PASS WITH PROTOTYPE GATE**.
- Interactive Qt may use QGraphicsBlurEffect for responsiveness.
- Canonical parity comes from FFmpeg truth-preview/final render.
- Final candidate backend: named `gblur` filter with commandable sigma driven by `sendcmd`.
- Blur pipeline must test premultiply → blur → unpremultiply and transparent-edge artifacts.
- K3 promotion is forbidden unless frame-accurate Windows command timing passes a real micro-render.

### Shadow
- **PASS WITH PROTOTYPE GATE**.
- Qt interaction may use QGraphicsDropShadowEffect.
- Final render derives an alpha branch, offsets it, applies named commandable gblur, colors/modulates it, then composites behind the original group.
- Exact FFmpeg truth-preview is the parity authority.
- Transparent-edge and alpha golden tests are mandatory.

### Glow
- **PASS WITH PROTOTYPE GATE**.
- Implement as a blurred/colorized alpha-derived branch composited behind/around the original visual.
- Use the same command scheduler and alpha discipline as shadow.
- Qt approximation is not parity authority.

### Bezier / velocity / overshoot
- GO at architecture level.
- Implement once in the shared scalar evaluator/compiler contract, not separately per property.
- Preview and FFmpeg must consume the same locked STEP 01 mathematics.
- Unsupported advanced interpolation in an advanced-v1 project is an ERROR, never silent linear fallback.

## Heavy parameter command scheduler
- Scope command files per Scene render job, not the entire project.
- Sample the canonical scalar evaluator at output-frame timestamps.
- Round blur sigma commands to 0.01 px and deduplicate unchanged consecutive values.
- Every commandable filter instance gets a unique stable target name.
- Command files live only in the staged render workspace and follow cleanup/cancellation policy.
- Windows non-ASCII temporary paths must be included in proof cases.

## Feature-based capability probing
Do not gate advanced-v1 by FFmpeg version string alone.

Probe and cache a capability fingerprint for:
- dynamic spatial alpha expressions;
- named `gblur` availability;
- runtime sigma commands via `sendcmd`;
- alphaextract/alphamerge plus premultiply/unpremultiply path;
- overlay frame expressions;
- existing scale/rotate/alpha transform baseline.

Capability requirements are project-aware:
- opacity/crop/mask projects do not require the heavy blur-command capability;
- blur/shadow/glow projects do;
- missing required capability in an advanced-v1 project produces `ADVANCED_BACKEND_UNAVAILABLE` ERROR before render.

## Performance gates
Reference comparison is the same machine/toolchain/input on the accepted v0.2.0 path.

- Lightweight Qt preview: target >=30 fps at 1280x720 with up to 2 assets.
- No repeated GUI-thread stall >100 ms.
- Truth-preview cancellation acknowledgement target: <500 ms.
- opacity/crop/mask render: <=2.5x v0.2.0 baseline.
- one blur track: <=4x baseline.
- blur + shadow + glow combination: <=8x baseline.
- preview cache must be bounded.

Exceeding a budget is a gate failure until optimized or scope is revised explicitly.

## Required real-render proof matrix
- keyframe endpoints and midpoints;
- hold/linear/easing plus Bezier velocities 0/1/4 and overshoot 0/.25/.50;
- opaque RGB and RGBA assets;
- SINGLE and DOUBLE Scene;
- 1280x720, 1920x1080, 3840x2160;
- 30 fps plus 60 fps smoke;
- individual advanced properties and combined stage-order cases;
- cancellation while heavy render is active;
- transparent-edge golden tests;
- old v0.2.0 project without advanced-v1 marker remains unchanged.
